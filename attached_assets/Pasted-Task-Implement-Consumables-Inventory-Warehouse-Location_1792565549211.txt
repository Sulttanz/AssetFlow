Task: Implement Consumables Inventory, Warehouse Locations, and Service Request Stock Deduction

Please update our Purchase Orders, Consumables Inventory, and Service Request Fulfillment modules with the following end-to-end capabilities:

1. **PO Item Classification & Receiving (`shared/schema.ts`):**
   - Add `itemType` ('asset' | 'consumable') to Purchase Order items.
   - Receiving 'asset' items generates individual tagged records in the Asset Register (`assets`).
   - Receiving 'consumable' items increases stock in the Consumables Inventory table (`consumables`) at a specified Warehouse/Storage Location.

2. **Consumables & Warehouse Inventory Register (`/consumables` or `/inventory`):**
   - Create schema/table for consumables: `name`, `category` (Toner, Peripherals, Cables, etc.), `modelPartNumber`, `quantityInStock`, `minReorderLevel`, `warehouseLocationId` / `storageRoom`, `unitCost`, `vendorId`.
   - Add a "Manual Issue / Transfer" modal allowing staff to issue stock directly to an employee or transfer between storage locations.
   - Display items in a paginated table (20/50 rows per page) with search, category filters, DD-MM-YYYY dates, and Low Stock warning badges.

3. **Service Request Stock Fulfillment & Automated Deduction:**
   - Link Consumable Items to Service Catalog Items (`catalog_items`).
   - On the Service Request Tracker (`/service-requests/tracker`), when fulfilling a request linked to a consumable item:
     - Allow the IT agent to select the source Warehouse/Storage Room.
     - Validate available stock before completing.
     - Upon clicking "Fulfill / Deliver", execute a database transaction that automatically deducts the requested quantity from stock and logs an immutable `consumable_dispatch_log` (recording Requester, Agent, Date, SR #, and Quantity).

4. **Reorder Integration:**
   - Add a "Create Draft PO for Low Stock" action on consumable items that fall below `minReorderLevel`.

Please apply these updates, execute required migrations, and ensure `npm test` and `npm run check` pass cleanly.
