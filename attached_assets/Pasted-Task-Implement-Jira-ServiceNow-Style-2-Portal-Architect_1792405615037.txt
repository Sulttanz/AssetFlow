Task: Implement Jira / ServiceNow Style 2-Portal Architecture (Self-Service Portal vs. Agent Workbench)

Goal: Build a dedicated End-User Self-Service Portal (`/portal`) for regular employees to report incidents, submit service requests, and propose change requests, while reserving the management queues (`/incidents`, `/service-requests`, `/changes`) strictly for IT Agents and Administrators.

Please execute the following updates:

1. **Create End-User Self-Service Portal Page (`client/src/pages/portal.tsx` & Route `/portal`):**
   - Build a clean, consumer-style Help Center dashboard containing:
     * **Integrated Hero Search:** Single search bar querying Knowledge Base articles and Service Catalog items simultaneously.
     * **Intake Action Cards:**
       1. "Report an Issue" -> Opens Incident submission modal/drawer.
       2. "Request Service or Hardware" -> Opens Service Catalog / Service Request modal.
       3. "Propose a Change" -> Opens Change Request intake form (for department leads/employees requesting business/system changes).
       4. "Browse Knowledge Base" -> Direct link to KB articles.
     * **My Requests & Activity Tracker:** A clean table listing ONLY tickets created by or requested for the logged-in user (`requester_id` / `creator_id`), displaying Ticket ID, Title, Type (Incident / Request / Change), Status Badge, Submitted Date, and Target Date.

2. **Role-Based Routing & Access Protection (`client/src/App.tsx` & `sidebar.tsx`):**
   - Automatically redirect non-IT end-users to `/portal` upon login.
   - Restrict full workbench pages (`/incidents`, `/service-requests`, `/changes`, `/problems`) so that users without Agent/Manager/Admin roles are redirected to `/portal` if accessed via direct URL.
   - Update sidebar navigation:
     * Regular Users see: "Self-Service Portal" and "Knowledge Base".
     * IT Staff / Admins see: Both "Self-Service Portal" and full "IT Service Management" workbench queues.

3. **Backend API Scope Verification (`server/routes.ts`):**
   - Ensure `/api/incidents`, `/api/service-requests`, and `/api/changes` endpoints strictly filter records based on role: non-agent users querying these endpoints only receive records where they are the creator or requester.

Please execute these changes, verify type safety with `npm run check`, and build the application cleanly.
