Task: Implement & Harden Phase 1 Module Registry and Dynamic Feature Toggles

Goal: Ensure that the application enforces strict module toggling for Asset Management, IT Service Management (ITSM), Risk Management, and future modules (such as Project Management). Toggling a module off must dynamically hide all associated frontend sidebar items/routes and block corresponding backend API endpoints.

Please execute the following updates:

1. Centralized Module Registry (`shared/schema.ts` & `server/storage.ts`):
   - Verify/update the `module_settings` table to store module flags:
     * `asset_management` (Core module, default enabled)
     * `itsm` (Independently toggleable)
     * `risk_management` (Independently toggleable)
     * `project_management` (Add initial placeholder flag for upcoming module)
   - Ensure helper methods exist in `storage.ts` to get and update module states dynamically.

2. Backend API Route Guards (`server/routes.ts` & Middleware):
   - Create/refactor express middleware `checkModuleEnabled(moduleKey: string)`.
   - Apply this middleware to every API route group:
     * `/api/assets/*`, `/api/assignments/*`, `/api/maintenance/*` -> require `asset_management`
     * `/api/incidents/*`, `/api/service-requests/*`, `/api/changes/*`, `/api/problems/*` -> require `itsm`
     * `/api/risks/*` -> require `risk_management`
   - If a request hits a disabled module endpoint, return HTTP status `403 Forbidden` with a clear JSON message: `{ "error": "Module [module_name] is currently disabled." }`.

3. Frontend UI Navigation Guards (`client/src/App.tsx` & `sidebar.tsx`):
   - Ensure the sidebar navigation dynamically reads module states from `/api/module-status` or app settings.
   - Completely hide sidebar menu sections and sub-links when a module is disabled.
   - Wrap protected frontend page routes in a module guard component that redirects to `/dashboard` or shows a "Module Disabled" fallback screen if a user attempts to manually navigate via URL to a disabled module route.

4. System Settings Control (`client/src/pages/settings.tsx`):
   - Ensure the Module Settings panel under System Settings displays clean toggle switches for administrators to enable or disable ITSM, Risk Management, and Project Management in real-time.

Please test that toggling a module off in Settings immediately updates the UI navigation and blocks the backend API endpoints cleanly, then verify with `npm run check`.
